# 메리츠증권 주식 연동 설계 (v2)

기존 가계부 시트(`docs/superpowers/specs/2026-10-06-household-budget-design.md`)에 메리츠증권 Open API로 보유 종목과 금액을 자동으로 가져오는 기능을 더한다.

## 목표
- 메리츠증권 슈퍼365 계좌의 순자산·보유 종목·원화/외화 보유금액을 시트에 자동 반영한다.
- `자산` 탭의 메리츠증권 행에는 순자산, 새 `주식` 탭에는 종목(티커)·평단가·수량·금액, 새 `메리츠` 탭에는 상세 현황(참고 시트 `주식 포트폴리오 통합본`의 Portfolio·Stock List 구성)을 보여 준다.

## 결정된 사항 (사용자 확정)
| 항목 | 결정 |
|---|---|
| 실행 위치 | 구글 시트 안 Apps Script (`UrlFetchApp`), PC가 꺼져 있어도 갱신 |
| 구조 | 접근안 1 — 스크립트는 API 원본값을 숨김 탭 `메리츠원본`에만 쓰고, 화면 탭은 전부 수식 |
| 자산 잔액 | 메리츠증권 행은 API 값으로 채움 (내역·초기잔액으로 계산하지 않음) |
| 코드 생성 도구 | `meritz-codegen` MCP 등록 완료 (호출 코드 작성 참고용). 계좌 데이터는 가져오지 않음 |

## 범위 밖
주문·환전·예약주문(조회 전용), 실시간 시세(WebSocket), 메리츠 외 증권사, 실현손익 이력, 배당·수수료·세금, 갱신 실패 메일 알림.

## 전제와 미확인 항목
- 앱 Key/Secret은 **아직 없다.** 개발자 포털(openapi.imeritz.com)이 2026-10-06 접속되지 않았고, 슈퍼365 계좌로 신청 가능한지 공식 문서로 확인하지 못했다. 공식 명세(`openapi.json`, 2026-10-02판)에 `Super365 발행어음`·`슈퍼365-USD RP` 상품 코드가 나와 가능성은 있다.
- `quant_system_v2`의 메리츠 코드는 접속 주소가 공식 주소와 달라 재사용하지 않는다.
- **키를 받은 뒤에만 확인되는 위험** — 구현은 이것과 무관하게 진행한다.
  1. 구글 서버에서 `:9443` 포트로 접속·토큰 발급이 되는지
  2. 키가 특정 서버(IP)에서만 통하는지
  3. `mac_address` 헤더를 서버가 실제로 검사하는지
  4. **슈퍼365의 자동투자분(발행어음·RP)이 총자산에 들어가는지.** 명세상 총자산은 `tfam + mksc_vltn_amt + frcr_tfam`이고, 자동투자는 `wtmn_able_atmt_invt_amt`("자동투자 상품에서 인출 가능한 금액")로 따로 내려온다. 이 값이 총자산에 이미 포함되는지 알 수 없으므로 **합산하지 않고 따로 표시**하며, 키 발급 뒤 메리츠 앱 화면의 총자산과 대조해 결정한다.
- **대체 경로:** 1~3 중 하나라도 막히면 이 PC의 Python이 같은 API를 호출해 `메리츠원본`에 같은 형식으로 쓴다. 화면 탭은 바뀌지 않는다.

## API (공식 명세 기준)
- 기본 주소 `https://openapi.imeritz.com:9443`. 토큰 `POST /oauth2/token` (form: `grant_type=client_credentials`, `client_id`, `client_secret`, `scope=login`), 유효기간은 메리츠 `api_conventions`가 12시간이라고 밝히고(`openapi.json` 예시는 604800초), 코드는 응답의 `expires_in`을 그대로 쓴다. 같은 앱키로 발급한 토큰은 하나이고, 토큰 폐기 호출은 그 앱키의 모든 세션을 끊으므로 폐기 호출은 쓰지 않는다.
- 모든 조회: 헤더 `mac_address`(12자리), `Authorization: Bearer <토큰>`.
- 호출하는 경로는 토큰 발급 + 조회 4개뿐이다. 주문·환전 경로는 코드에 없다.

| 조회 | 경로 | 쓰는 값 |
|---|---|---|
| 총자산 | `GET /accounts/v1/me/valuation` | `aset_vltn_amt` 총자산(= `tfam + mksc_vltn_amt + frcr_tfam`), `tfam` 원화 현금, `mksc_vltn_amt` 유가증권 평가, `frcr_tfam` 외화 예수금 원화 환산, `loan_amt` 대출, `wtmn_able_atmt_invt_amt` 자동투자 인출가능액 |
| 보유 종목(원화 기준) | `GET /accounts/v1/me/holdings` | 행마다 `pros_trgt_cls_code`, `mksc_cls_name`, `iscd`, `isnm`, `rmnd_qty`, `rmnd_dqty`, `byng_unpr`, `byng_amt`, `vltn_amt`, `vltn_prls_amt`, `loan_amt` |
| 해외 종목(거래 통화 기준) | `GET /accounts/v1/me/overseas/holdings` | `iscd`, `ovrs_stck_symb_iscd`, `isnm`, `crcd`, `rmnd_dqty`, `psnt_prc`, `byov_camt`, `frcr_vltn_amt`, `vltn_prls_camt`, `exrt` |
| 외화 예수금 | `GET /accounts/v1/me/overseas/currencies` | 통화별 `crcd`, `frcr_amt`, `vltn_exrt`, `ovrs_stck_vltn_amt` |

### 보유 종목을 만드는 규칙 (명세의 경고를 그대로 반영)
- **종목 목록과 원화 금액은 `/me/holdings` 하나로 만든다.** 이 응답에는 국내(`1`)·해외(`J`)가 섞여 오고, 해외 행의 매입금액·평가금액·평가손익은 원화 환산액이다. 명세상 이 평가금액 합은 `mksc_vltn_amt`와 맞는다.
- `pros_trgt_cls_code`가 `1`·`J`가 아닌 값도 올 수 있다(명세: "목록에 없는 값이 내려오더라도 오류로 다루지 마십시오"). 이런 행은 버리지 않고 구분 `기타`(종목명은 `isnm`)로 보여 주고 합계에 넣는다.
- **같은 종목이 여러 행으로 온다**(잔고 유형·대출 건이 다르면 나뉨). 화면에는 `iscd`별로 묶어 한 줄로 보여 주고, 수량·매입금액·평가금액·평가손익은 더한다. 평단가는 `매입금액 ÷ 수량`이 아니라(원화 금액과 외화 단가가 섞임) 아래 규칙으로 정한다.
- 국내 수량 = `rmnd_qty + rmnd_dqty` (소수점 거래분이 따로 옴). 국내 평단가 = 묶은 행의 `byng_amt` 합 ÷ 수량 (원). 원화 수익률 = 평가손익 합 ÷ 매입금액 합.
- 해외 종목은 `/overseas/holdings`를 `iscd`별로 묶어 **거래 통화 열만** 덧붙인다: 통화(`crcd`), 수량(`rmnd_dqty` 합), 평단가 = `byov_camt` 합 ÷ 수량, 현재가 `psnt_prc`, 평가금액(외화) `frcr_vltn_amt` 합, 수익률(외화) = `vltn_prls_camt` 합 ÷ `byov_camt` 합. 해외 수량은 이 응답의 값을 쓴다(명세상 해외는 `rmnd_dqty` 하나에 전체 수량).
- 짝이 맞지 않는 경우(한쪽 응답에만 있는 해외 종목)는 있는 값만 보여 주고 상태에 "해외 종목 불일치 N건"을 기록한다. 합계는 언제나 `/me/holdings` 원화 금액으로만 내므로 이중 계산이 생기지 않는다.
- 티커 표시: 국내 `iscd`의 앞 `A`를 뗀 6자리, 해외는 `ovrs_stck_symb_iscd`(없으면 `iscd`의 `.` 앞).
- 수익률은 응답의 `ert`·`vltn_ert`(%) 대신 묶은 합계로 다시 계산한다(행을 묶으면 행별 수익률을 그대로 쓸 수 없음).

### 검산 (명세가 "맞는다"고 한 관계만 쓴다)
- `/me/holdings`의 평가금액 합 ≈ `mksc_vltn_amt`
- `/me/holdings`의 해외(`J`) 평가금액 합 ≈ 외화 예수금 응답의 `ovrs_stck_vltn_amt` 합
- 세 조회가 몇 초 간격으로 따로 오므로 시세가 움직일 수 있다. 차이가 1%를 넘을 때만 `메리츠` 탭에 경고한다.
- `byng_amt`(매입금액)는 명세상 두 조회의 환율 기준이 달라 어긋나는 것이 정상이므로 검산하지 않는다.

### 순자산
- 화면과 `자산` 탭에 쓰는 메리츠 금액 = `aset_vltn_amt − loan_amt` (**순자산**). 총자산은 대출을 빼지 않은 값이라, 신용·담보대출이 있으면 그대로 쓰면 재산이 부풀려진다. 대출이 0이면 총자산과 같다.

## 데이터 구조

### 숨김 탭 `메리츠원본` (스크립트가 쓰는 유일한 곳)
고정 위치 블록. 숫자 문자열은 숫자로 바꿔 쓰고, 묶기(`iscd`별 합산)는 스크립트의 순수 로직이 한다. 수익률 같은 파생값은 화면 수식이 계산한다.

| 블록 | 위치 | 내용 |
|---|---|---|
| 상태 | `A1:E5` | 1행 머리글, 2~5행 조회별(총자산·보유종목·해외보유·외화예수금): 조회명 · 상태(`성공`/`자료없음`/`권한없음`/`오류`/`키없음`) · `rsp_cd` · 메시지 · 마지막 성공 시각 |
| 요약 | `G1:H8` | 총자산, 원화 현금, 유가증권 평가, 외화 예수금(원), 대출, 자동투자 인출가능액, 순자산, 갱신 시각 |
| 외화 예수금 | `J1:N6` | 1행 머리글 + 통화별 최대 5행: 통화 · 예수금 · 환율 · 예수금(원) · 해외주식 평가(원) |
| 종목 | `A10:N109` | 1행(10행) 머리글 + 최대 100종목: 구분(국내/해외/기타) · 티커 · 종목명 · 수량 · 평단가(원) · 매입금액(원) · 평가금액(원) · 평가손익(원) · 대출(원) · 통화 · 평단가(외화) · 현재가(외화) · 매입금액(외화) · 평가금액(외화) |

- 조회가 성공한 블록만 지우고 한 번에 새로 쓴다. 실패한 조회의 블록과 그 마지막 성공 시각은 그대로 둔다.
- 종목 블록은 `/me/holdings`(필수)와 `/overseas/holdings`(외화 열) 두 조회로 만든다. `/me/holdings`가 실패하면 종목 블록을 갱신하지 않는다. `/overseas/holdings`만 실패하면 원화 열은 갱신하고 외화 열은 비운 뒤 상태에 기록한다.
- 100종목을 넘으면 평가금액 큰 순서로 100개만 쓰고 상태에 "종목 수 초과"를 기록한다(합계는 요약 블록의 API 값이라 영향 없음).
- **실제 운영 시트에는 샘플 값을 넣지 않는다.** 키를 받기 전에는 `메리츠원본`이 비어 있고, 화면은 "아직 갱신 전"을 보여 준다. 샘플은 임시 시험 시트에서만 쓴다.

### `자산` 탭 변경
- G열 `연동`(드롭다운: `메리츠`), H열 `연동 상태`(수식, 보호).
- 연동된 행의 잔액(E) = `메리츠원본`의 순자산. 순자산이 숫자가 아니면(한 번도 성공 못 함) 기존 계산식으로 되돌아간다.
- H열: 연동된 행에 "메리츠 MM/DD HH:MM" 또는 "미갱신". 마지막 성공이 3일보다 오래되면 "오래됨 (MM/DD)"으로 표시해 낡은 값임을 알린다. 연동되지 않은 행은 빈 칸.
- 연동된 행의 초기 잔액·적립 카테고리는 무시된다(사용법에 안내). 메리츠로 보낸 이체 내역은 그대로 기록되고, 보낸 통장의 잔액에서는 계속 빠진다.

### `주식` 탭 (보기 전용, `메리츠원본`을 읽는 수식)
- 맨 위 요약: 순자산 · 유가증권 평가 · 원화 현금 · 외화 예수금(통화별 금액과 원화) · 자동투자 인출가능액(별도 표시, 합산 안 함) · 평가손익 · 수익률 · 마지막 갱신 시각 · **지금 갱신** 체크박스.
- 종목 표 열: 구분 · 티커 · 종목명 · 수량 · 평단가(원) · 매입금액(원) · 평가금액(원) · 평가손익(원) · 수익률(원화 기준) · 통화 · 평단가(외화) · 현재가(외화) · 평가금액(외화) · 수익률(외화 기준) · 비중. 참고 시트 `Stock List`의 열(종목코드·종목명·잔고수량·현재가·평균매입가·평가손익·수익률·평가금액·매입금액)을 모두 포함한다. 국내 종목은 외화 열이 비어 있다. 열 이름에 USD를 고정하지 않는다(종목마다 통화가 다를 수 있음).
- 국내 종목의 현재가(원)는 `평가금액 ÷ 수량`으로 보여 준다(명세: 평가금액 = 응답의 현재가 × 수량).
- 수익은 빨강, 손실은 파랑(한국 증시 관례). **`주식`·`메리츠` 탭에서만** 적용하며, 가계부 구분 색(지출 빨강·수입 파랑)과 뜻이 다르므로 사용법에 명시한다.
- "지금 갱신" 체크박스 칸은 보호 범위에서 뺀다(보기 탭은 경고형 보호라 빼지 않으면 체크할 때마다 경고 창이 뜸).

### `메리츠` 탭 (상세, 보기 전용)
- 큰 글씨 카드: 순자산 · 평가손익 · 수익률 · 보유 종목 수(수익 N / 손실 N).
- 차트: 자산 구성(유가증권·원화 현금·외화 예수금) 도넛, 종목별 비중 막대, 종목별 수익률 막대, 국내/해외 비중.
- 맨 위에 조회별 상태와 검산 경고를 표시한다.
- 서식은 기존 `styling.py` 규칙(기본 글씨 12, 머리글 13 굵게, 제목 22, 요약 숫자 20, 탭 색, 보기 탭 눈금선 숨김)을 따른다.

## 갱신

### 시점
- 시간 트리거: 매일 07시대와 16시대 각 1회. Apps Script의 `atHour`는 정각이 아니라 **그 시각부터 1시간 안 어느 때**에 실행된다. 07시대는 미국 장 마감(05~06시) 뒤, 16시대는 국내 장 마감(15:30) 뒤다.
- 수동: `주식` 탭 "지금 갱신" 체크박스.
  - 단순 `onEdit`은 외부 호출이 불가능하므로, 체크박스 전용 **설치형 onEdit 트리거**를 쓴다. 함수 이름은 `onEdit`이 아닌 `onEditMeritz`로 한다(이름이 `onEdit`이면 단순 트리거로도 한 번 더 실행됨). 이 함수는 해당 칸이 아니면 즉시 끝낸다.
  - 기존 단순 `onEdit`은 이 칸을 무시한다.
  - 체크는 즉시 해제하고, 결과는 상태 블록과 갱신 시각으로 알린다.
- **동시 실행 방지:** 시간 트리거와 체크박스가 겹치면 스크립트 잠금(`LockService.getScriptLock`)으로 하나만 실행하고, 다른 하나는 "이미 갱신 중"으로 끝낸다.

### 호출 규칙
- 4개 조회를 순서대로 부르고 호출 사이에 0.3초 쉰다.
- `muteHttpExceptions: true`. 오류는 모두 HTTP 500으로 오므로 성공 판정은 `rsp_cd`로 한다. 조회 성공 코드는 `5766`.
- 응답이 JSON이 아니거나 `data`의 형태가 기대와 다르면(객체/배열) 그 조회는 `오류`로 처리한다.
- 코드별 처리:

| `rsp_cd` | 처리 |
|---|---|
| `5766` | 성공 |
| `5820` | `자료없음` — 빈 표로 반영(오류 아님) |
| `0760` | `권한없음` — 재시도 없음 |
| `EGW00200` | 초당 호출 초과 — 1초 쉬고 최대 3회 재시도, 그래도 같으면 `오류` |
| 그 밖 (`IGW50004` 등) | `오류` — 코드와 `rsp_msg` 기록 |

- **연속조회 금지:** 요청에 `tr_cont`를 절대 넣지 않는다(해외 보유 조회에 `"1"`을 넣으면 오류 없이 빈 결과가 옴). `/me/holdings`의 응답 `tr_cont`가 `"1"`이어도 다음 페이지를 요청하지 않는다(명세: 같은 내역이 끝없이 되풀이됨).
- `/me/holdings`는 `nthn_rmnd_incu_yn`을 보내지 않는다(기본 `N` = 잔고 0 종목 제외). 그래도 수량이 0인 행은 버린다.
- 숫자 변환 결과가 숫자가 아니면 그 조회는 `오류`로 보고 덮어쓰지 않는다.

### 토큰
- 토큰과 만료 시각을 저장해 다시 쓴다. **갱신마다 새로 발급하지 않는다**(발급 횟수 제한 여부를 모르므로).
- 남은 시간이 1시간 미만이면 미리 새로 발급한다(유효기간 12시간).
- 조회가 `5766`·`5820`·`0760`·`EGW00200`이 아닌 코드로 실패하면 토큰 문제일 수 있으므로, 한 번의 갱신에서 **딱 한 번만** 토큰을 새로 받아 실패한 조회를 다시 시도한다.
- 토큰 발급이 실패하면 모든 상태를 `오류`(토큰 발급 실패)로 기록하고 끝낸다.

### 예외와 실패 메일
- 갱신 함수는 예외를 밖으로 던지지 않는다(시간 트리거 함수가 예외를 던지면 구글이 소유자에게 실패 메일을 보냄). 예외는 잡아서 상태 블록에 기록한다.
- 키가 아직 없으면 상태를 `키없음`으로 기록하고 조용히 끝낸다(키 발급 전에도 트리거가 돌아도 문제없음).

## 보안
- **키·MAC·토큰은 소유자(신랑)의 사용자 속성(`PropertiesService.getUserProperties`)에 둔다.** 스크립트 속성은 편집 권한자가 Apps Script 프로젝트 설정 화면에서 바로 볼 수 있지만, 사용자 속성은 그 사람 본인 실행에서만 읽힌다. 시간 트리거와 설치형 트리거는 만든 사람(소유자) 권한으로 실행되므로 이 값을 읽을 수 있다.
- **입력 방법:** PC에서 시트 메뉴 `메리츠 > 키 입력`(단순 `onOpen`이 만드는 메뉴) → 입력 창에 App Key, App Secret, MAC 주소(12자리, 윈도우 `getmac` 결과에서 `-` 제거) 순서로 넣는다. 입력값은 시트·로그·git·대화에 남지 않는다. 같은 메뉴에 `키 삭제`도 둔다.
- **`setupTriggers`와 키 입력은 반드시 소유자가 실행한다.** 배우자가 실행하면 트리거가 배우자 권한으로 돌고 소유자의 사용자 속성을 읽지 못해 `키없음`이 된다.
- 남는 위험: 편집 권한자는 스크립트 코드를 고칠 수 있고, 트리거는 소유자 권한으로 돌므로, 악의적으로 코드를 바꾸면 키를 빼낼 수 있다. 부부 공유 범위에서 받아들이며 사용법에 적는다. 노출이 의심되면 포털에서 재발급하고 `키 입력`을 다시 한다.
- 키·토큰·`client_secret`은 어떤 칸·로그·오류 메시지에도 쓰지 않는다. 오류 메시지는 API의 `rsp_cd`·`rsp_msg`만 쓴다.
- 키의 권한 범위(조회 전용 여부)는 포털 설정이므로 신청할 때 확인한다.
- 새 기능은 외부 요청 권한이 필요하므로, 배포 후 소유자가 `setupTriggers`를 한 번 더 실행해 권한을 허용한다.

## 운영 중인 시트에 적용 (마이그레이션)
- 운영 시트(`1oVOiX5…`)에는 실제 가계부 데이터가 있으므로 **새로 만들지 않는다.** `migrate_meritz.py`가 탭 추가(`주식`·`메리츠`·`메리츠원본`), `자산` G·H열 추가, 수식·서식·차트·보호 설정을 **제자리에서** 한다.
- 이미 있는 탭·열은 건너뛰어 두 번 실행해도 안전하다(idempotent). 기존 데이터 칸은 쓰지 않는다.
- 새로 만드는 시트(`build_budget.py`)에도 같은 탭이 들어가도록 같은 함수를 공유한다.

## 시험
- **Node(시트 없이):** `rsp_cd` 분류와 재시도, 비-JSON·형태 오류, 숫자 변환 실패, 같은 `iscd` 여러 행 묶기, 국내 수량 = 정수+소수, 기타 구분 유지, 해외 외화 열 짝맞추기와 불일치 기록, 이중 계산 없음(합계 = `/me/holdings` 원화 합), 순자산 = 총자산 − 대출, 검산 판정, 토큰 만료 24시간 판정과 갱신당 1회 재발급, 100종목 초과, 요청에 `tr_cont`가 들어가지 않음.
- **pytest:** `메리츠원본` 블록이 겹치지 않음, 화면 수식이 올바른 블록을 가리킴, 자산 E·H 수식(순자산·되돌림·오래됨), 차트 범위, 체크박스 칸 보호 제외, 마이그레이션 요청이 기존 데이터 범위를 쓰지 않음.
- **통합(키 없이):** 임시 시트를 만들어 샘플을 `메리츠원본`에 쓰고 `주식`·`메리츠`·`자산` 값을 읽어 기대값과 비교한 뒤 휴지통으로 보낸다. 공유하지 않는다. 운영 시트에는 마이그레이션 후 "아직 갱신 전" 상태와 기존 자산 잔액이 그대로인지 확인한다.
- **키 발급 뒤 순서:** ① 9443 접속·토큰 → ② IP 제한 → ③ MAC 검사 → ④ 조회 4개 실제 응답 → ⑤ 메리츠 앱 화면의 총자산·종목과 대조(특히 자동투자분 포함 여부) → ⑥ 폰에서 "지금 갱신" 체크. ①~③에서 막히면 대체 경로.

## 구현 순서
1. 순수 로직(`meritz_logic.gs`)과 Node 시험, 시험 샘플

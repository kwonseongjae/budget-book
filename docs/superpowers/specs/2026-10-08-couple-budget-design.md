# 부부 가계부 확장 설계 — 사람별 예산·정산·자동 추천·순자산 추이·월간 결산 (2026-10-08)

## 배경
2026-10-08 실사용 점검에서 나온 문제와, 사용자 결정 3가지를 반영한다.
- 같은 카테고리라도 사람마다 금액이 다르다 → **예산을 사람별로** (합계는 자동)
- 공동 지출 정산 → **반반(50:50)**
- 추가 기능 → **카테고리 자동 추천, 순자산 추이, 월간 결산 메일** (카드 청구액 예측은 제외)

## 1. 사람별 예산 (설정 탭)
- 설정 `K1:M1` = 사용자 슬롯 3개 머리글 `=E2&" 예산"`, `=E3&" 예산"`, `=E4&" 예산"` (신랑·신부·공동). 입력은 `K2:M60`.
- 설정 `C` 열(월 예산)은 `C1` ARRAYFORMULA `=K+L+M` 합계로 바꾸고 보호(경고). 대시보드·차트의 기존 참조(VLOOKUP 3열)는 그대로 동작.
- 열 삽입 대신 오른쪽에 붙이는 이유: 기존 열(E 사용자, G:H 통화, J 설정)을 참조하는 수식·스크립트 상수가 많아 밀면 깨진다. 폰에서 멀어지는 문제는 설정 A열 고정으로 완화.
- 한계: 사용자 슬롯 3개 고정 (`ponytail:` 4명 이상이면 슬롯 추가).
- **운영 시트 이전**: 기존 C값은 공동 열(M)로 옮긴다. 단 수입 카테고리 `월급1` → 신랑(K), `월급2` → 신부(L). 이전 뒤 사용자가 주택청약·보험 등을 사람별로 나눠 적는다.

## 2. 부부 탭 (새 보기 탭, sheetId 1700)
- `B1` 월 선택 (다른 보기 탭과 같은 `month_pick`).
- **사람별 요약**: 사용자 3명 × [수입, 지출, 저축·기타, 남은 돈].
- **카테고리 × 사람 표**: 지출·저축 카테고리 행마다 사람별 [지출, 예산, 사용률] (사용률 80%/100% 색).
- **정산(반반)**: 사용자=`공동`인 나가는 돈 중, 결제수단의 소유자가 신랑인 합계 A, 신부인 합계 B → `|A−B|/2`를 "신부 → 신랑 N원"처럼 표시. 공동 소유 자산으로 낸 돈은 정산 대상 아님. 소유자 미지정 결제수단 건수도 표시.
- 자산 탭 `I` 열 **소유자**(드롭다운: 설정 사용자 목록) 추가 — 자산 탭 8열 → 9열.

## 3. 예산 알림 (logic.gs·triggers.gs)
- 키를 `월|카테고리|사용자|단계`로, 사람별 예산과 사람별 지출을 비교. 예산 칸이 빈 사람은 알림 없음.
- 구분이 `지출`인 카테고리만 알림. 저축은 '예산 초과' 대상이 아님 (10/7 주택청약 오발송 원인).
- 받는 사람(J4)은 시트 편집자·소유자 이메일만 허용 (편집자가 외부 주소를 넣어 지출 내역을 내보내는 경로 차단).

## 4. 카테고리 자동 추천
- 순수 함수 `suggestCategory(history, memo)`: 과거 내역의 메모(가맹점)가 같으면(공백 정규화 후 완전 일치, 없으면 서로 포함) 가장 많이 쓴 [구분, 카테고리]. 동률이면 최근 것. 없으면 null.
- 적용 지점 2곳: ① 문자입력 가져오기 시 카테고리 자동 채움(+구분) ② 내역에서 메모를 입력했는데 카테고리가 비어 있으면 채움(단순 onEdit).
- 추천으로 채운 칸은 덮어쓰지 않는다(빈 칸에만).

## 5. 순자산 추이
- 새 탭 `자산기록` (sheetId 1800, 보기 탭): `A` 월, `B` 순자산, `C` 자산 합계(카드 외), `D` 카드 잔액 + 꺾은선 차트.
- dailyJob이 매일 **이번 달 행을 덮어쓴다** → 한 달의 마지막 실행 값이 월말 값으로 남음. 트리거가 하루 빠져도 누락 없음.
- 값 출처: 자산 탭 E열(현재 잔액, 메리츠 연동 포함)과 B열(종류 `카드` = 부채).

## 6. 월간 결산 메일
- dailyJob: 오늘이 월 시작일(J2)이고 `알림기록`에 `report|YYYYMM`이 없으면 지난달 결산 발송 후 기록.
- 내용: 사람별 수입·지출·저축, 지출 상위 카테고리 5개, 사람별 예산 초과 카테고리, 정산 결과, 순자산 증감(자산기록 전월 대비).
- 집계는 순수 함수(`monthReport`)로 node 시험. 시트 수식과 같은 규칙(정산·나가는 돈 정의)을 시험으로 고정.

## 7. 점검에서 나온 수정
- **월말 예상 지출** (대시보드 F6): `지출 + 이번 달 아직 안 생긴 반복 지출 + 변동비 일평균 × 남은 일수` (현재 달만, 지난 달은 실제 지출).
- **미등록 결제수단 표시**: 내역 F·G열 값이 자산 목록에 없으면 빨간 배경 (하나카드·신한은행 같은 경우).
- **문자 붙여넣기 수식 주입 방지**: 가맹점·실패 문자가 `= + - @`로 시작하면 앞에 `'`.
- **token.json 위치**: `~/.config/budget-book/token.json`(권한 600)으로 이동, `BUDGET_TOKEN_FILE`로 바꿀 수 있음. 기존 파일은 이동 후 삭제. (D 드라이브는 chmod가 안 먹음)
- 사용법 탭에 부부·자산기록·자동 추천 안내 추가.

## 8. 메리츠 계좌 2개 (사용자 추가 요구, 10-08)
- 메리츠 Open API 조회는 `/accounts/v1/me/...` — 앱 Key가 곧 계좌. 두 사람은 각자 포털에서 앱 Key를 받는다.
- **슬롯**: 시트 소유자 = 슬롯1(신랑), 그 밖의 편집자 = 슬롯2(신부). `ponytail:` 2명 고정, 3번째 계좌가 생기면 슬롯 표에 한 줄 추가.
- 탭: 슬롯1 `주식·신랑`·`메리츠·신랑`(기존 `주식`·`메리츠` 이름 변경) + 숨김 `메리츠원본`, 슬롯2 `주식·신부`(1550)·`메리츠·신부`(1650) + 숨김 `메리츠원본2`(1450). 화면 수식·서식·차트는 슬롯마다 같은 생성기로 만든다.
- 키 입력: 누구나 자기 키를 **자기 사용자 속성**에 넣는다 (소유자 전용 제한 해제 — 갱신이 각자 권한으로 돌기 때문). 저장 슬롯은 입력자가 소유자인지로 정함.
- 자동 갱신: 메뉴 `메리츠 > 자동 갱신 켜기` = 호출한 사람의 갱신 트리거(07·16시 + 체크박스 onEdit)만 다시 만든다. 소유자의 `setupTriggers`는 그대로 전부(일일 작업 포함).
- 갱신은 실행자 슬롯의 원본 탭에만 쓴다. 잠금은 사용자 잠금(두 사람 갱신이 서로 막지 않게). 체크박스 onEdit은 두 사람 트리거가 모두 받지만 자기 슬롯의 주식 탭 H1일 때만 갱신.
- 자산 G열 연동 값: `메리츠·신랑` / `메리츠·신부` → 해당 원본 탭의 순자산(H7). 운영 시트 G열은 아직 비어 있어 이전할 값 없음.
- 보안 메모 갱신: 편집자가 코드를 고치면 상대 키를 빼낼 수 있는 위험은 이제 양쪽 모두에 해당 (부부 공유 범위에서 수용, README·사용법에 명시).

## 하지 않는 것 (이번 범위 밖)
- 카드 청구액 예측 (사용자 제외)
- 메리츠 키를 소유자 전용 별도 스크립트로 분리 (보안 '중' — 다음 라운드 후보)
- OAuth 범위를 `drive.file`로 축소 (브라우저 재인증 필요 — 사용자가 원하면 별도)
- 월급1·월급2 병합 (사람별 예산으로 가능해졌지만 기존 내역 변경이라 사용자 판단)

## 운영 적용 (migrate_couple.py, 반복 실행 안전)
탭 2개 추가, 자산 I열 추가, 설정 K:M·C 수식, 기존 예산 이전(한 번만: K:M가 모두 비어 있을 때만), 대시보드 F6, 조건부 서식, 사용법. 기존 입력 데이터(내역·반복·즐겨찾기)는 건드리지 않는다. 적용 전 시트 사본을 드라이브에 만든다(되돌리기용).

## 검증
- pytest(수식·요청 생성·이전 계획), node(추천·알림·정산·결산·서식 주입) — 새 기능마다 RED→GREEN.
- 임시 시트 통합 검증(`verify_couple.py`): 샘플 내역으로 부부 탭 값·정산·예상 지출이 기대값과 일치.
- 운영 적용 후: 오류 칸 0, 기존 내역 행 수·합계 불변, 설정 C 합계 = 이전 전 값.

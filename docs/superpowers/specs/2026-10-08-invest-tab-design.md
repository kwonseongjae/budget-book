# 투자 탭 설계 — 부부 주식 계좌 4개 합산과 증감 추이 (2026-10-08)

## 목적
부부의 주된 자산 형성 수단은 주식이다. 계좌 4개(신랑 메리츠, 신부 메리츠, 신랑 한투 ISA, 신부 한투 ISA)를 연동해
**부부 합산 금액**과 **증감 추이**를 한 탭에서 본다. 증감은 '평가금액'과 '투자원금'을 함께 보여 주어,
돈을 더 넣어서 늘었는지 주가가 올라서 늘었는지를 구분한다.

## 사용자가 정한 것
- 연동 방식: 시트 스크립트(Apps Script)가 4개 계좌를 조회하고, 조회가 안 되는 계좌는 직접 입력으로 대체 (A안).
  - B안(PC 파이썬 조회)은 구글 서버 → 9443 포트 접속이 막힐 때의 대안으로만 남긴다.
- 증감: 평가금액 + 투자원금을 함께.
- 화면: [투자] 탭 하나에 통합 (보이는 탭 수는 그대로 11개).
- 기록: 매일 기록, 그래프는 월별(월말 값) + 최근 30일 일별.

## 확인된 사실 / 확인 못 한 것
- 메리츠: 접근 토큰 하나가 계좌 하나에 묶인다(`/accounts/v1/me/...`). 계좌마다 앱 Key.
- 한투(KIS Developers): 계좌마다 앱 Key 발급. 공식 예제(koreainvestment/open-trading-api) 기준
  - 토큰 `POST /oauth2/tokenP` (실전 `https://openapi.koreainvestment.com:9443`), 헤더 `custtype: P`
  - 잔고 `GET /uapi/domestic-stock/v1/trading/inquire-balance`, tr_id `TTTC8434R`,
    필수 `CANO`(8자리)·`ACNT_PRDT_CD`(2자리)·`AFHR_FLPR_YN=N`·`OFL_YN=""`·`INQR_DVSN=02`·`UNPR_DVSN=01`·
    `FUND_STTL_ICLD_YN=N`·`FNCG_AMT_AUTO_RDPT_YN=N`·`PRCS_DVSN=00`·`CTX_AREA_FK100=""`·`CTX_AREA_NK100=""`
- 사용자 확인(10-08): 한투 Open API 신청 가능. 앱 Key는 아직 안 받음 — 신청 때 ISA 계좌를 고를 수 있는지 함께 본다.
- **확인 못 함**: ISA 계좌로 API 신청·잔고 조회가 되는지, ISA 상품코드, 응답 output2 항목 이름(예상: `nass_amt`
  순자산, `pchs_amt_smtl_amt` 매입금액 합계, `dnca_tot_amt` 예수금). → 첫 실제 응답으로 맞추고, 안 되면 직접입력.
- **확인 못 함**: 구글 서버에서 9443 포트 접속 (메리츠와 같은 위험).

## ① 화면: [투자] 탭 (sheetId 1900, 보임)
보이는 탭 순서에서 [주식_신랑] 자리에 들어간다. [주식_신랑]·[메리츠_신랑]·[주식_신부]·[메리츠_신부]는
숨김(`layout.TUCKED`)으로 옮기고 메뉴 '가계부'로 연다. 폰을 위해 세로로 쌓는다.

- 1행: 제목 `📈 우리집 투자` + H1 '지금 갱신 (내 계좌)' 체크박스
- 요약(KPI): 부부 합산 평가금액 · 투자원금 · 평가손익(금액·%) · 전일 대비 · 전월말 대비
- 계좌 표: 계좌 | 평가금액 | 원금 | 손익(수익률) | 마지막 갱신 | 상태 | 직접입력 평가 | 직접입력 원금
  - 행: 신랑 메리츠, 신랑 ISA(한투), 신랑 합계, 신부 메리츠, 신부 ISA(한투), 신부 합계
  - 상태: 자동 / 직접입력 / 키없음 / 오류(사유) / 오래됨(3일 넘게 갱신 없음)
  - 직접입력 칸에 값이 있으면 그 계좌는 자동 값 대신 직접입력 값을 쓴다. 비우면 자동으로 돌아간다.
- 그래프 1: 월별 추이 — 합산 평가금액·투자원금 (각 달 마지막 기록)
- 그래프 2: 최근 30일 — 합산 평가금액

## ② 데이터와 연동
**계좌 = 사람 × 증권사.** 사람 슬롯은 기존 규칙(시트 소유자 = 신랑, 그 밖의 편집자 = 신부) 그대로.

| | 메리츠 | 한투 ISA |
|---|---|---|
| 신랑 | 기존 슬롯 0 (`메리츠원본`) | 새 (`한투원본` 2행) |
| 신부 | 기존 슬롯 1 (`메리츠원본2`) | 새 (`한투원본` 3행) |

- 키: 각자 사용자 속성. 메리츠는 기존 그대로, 한투는 `KIS_APP_KEY`·`KIS_APP_SECRET`·`KIS_ACCOUNT`(`12345678-01`)·
  토큰 `KIS_TOKEN`·`KIS_TOKEN_EXP`. 시트·로그·오류 메시지·git·대화에 키를 쓰지 않는다.
- 메뉴: '메리츠' → **'증권 연동'**: 메리츠 키 입력 / 한투 ISA 키 입력 / 자동 갱신 켜기 / 내 키 삭제.
- 갱신: 기존 메리츠 트리거(07시대·16시대, '지금 갱신')가 실행자 자신의 두 계좌를 함께 조회한다. 한투 결과는 숨김
  탭 `한투원본`(sheetId 1950)의 실행자 행: 상태 | 코드 | 메시지 | 마지막 성공 | 평가금액 | 원금.
- 계좌별 두 숫자:

| | 평가금액 | 투자원금(추정) |
|---|---|---|
| 메리츠 | 총자산 − 대출 (기존 H7) | 매입금액 + 원화 현금 + 외화 현금 − 대출 (새 H9) |
| 한투 ISA | `nass_amt` | `pchs_amt_smtl_amt` + `dnca_tot_amt` |

  - 한계: 원금은 '매입금액 + 현금' 추정이라 팔아서 남긴 수익 현금도 원금으로 잡힌다. 정확한 순입금은 범위 밖.
- 매일 기록: 06시 일일 작업(소유자 권한, 한 곳·한 번)이 숨김 탭 `투자기록`(sheetId 2000)에 **전날 날짜** 한 줄을
  쓴다: 날짜 | 계좌 4개 × (평가, 원금) | 합계 평가 | 합계 원금 | 빠진 계좌 수. 같은 날짜 줄이 있으면 덮어쓴다.
  각 계좌 값은 [투자] 탭 계좌 표의 최종 값(직접입력 우선)을 읽는다. 주말도 기록(금요일 값)해 그래프에 빈칸이 없다.
- 그래프·증감 계산(시트 수식): 월별 = 투자기록에서 각 달 마지막 날짜 줄, 최근 30일 = 마지막 30줄,
  전일 대비 = 마지막 두 줄 합계 차, 전월말 대비 = 마지막 줄 합계 − 그 전 달 마지막 줄 합계. (메리츠 원금 H9는 `메리츠원본` 요약 블록 G9:H9 빈자리)
- [자산] 연동: G열 선택지에 `한투ISA_신랑`·`한투ISA_신부` 추가. 고른 계좌의 잔액 = 그 계좌 평가금액.
  ([자산기록] 순자산에도 자동 반영)

## ③ 오류 처리
| 상황 | 처리 |
|---|---|
| 키 없음 | 상태 '키없음', 직접입력 값이 있으면 사용 |
| ISA 조회 권한 없음 | 상태 '오류(권한 없음 — 직접입력 사용)', 재시도 안 함 |
| 9443 접속 실패 | 상태 '오류(접속 실패)' → B안 재논의 |
| 한투 토큰 발급 제한(1분 1회) | 토큰 24시간 재사용, 막히면 다음 갱신 때 |
| 조회 실패 | 그 계좌의 마지막 성공 값·시각 유지, 3일 넘으면 '오래됨' |
| 06시 기록 때 값 없는 계좌 | 빈칸, 합계는 있는 계좌만, '빠진 계좌 수' 기록 |

- 예외를 밖으로 던지지 않는다(구글 실패 메일 방지). 한투도 조회 전용 — 주문 경로는 코드에 없다.

## 시험
- node: 한투 응답 해석(정상·권한 없음·JSON 아님·숫자 아님), 평가·원금 계산, 계좌번호 나누기, 토큰 재사용, 투자기록
  날짜 덮어쓰기, 직접입력 우선, 빠진 계좌 수, 메리츠 원금(H9).
- pytest: 투자 탭 수식·서식·보호, 자산 연동 선택지, 탭 숨김·순서, 마이그레이션 반복 안전.
- 임시 시트 통합(`verify_invest.py`): 가짜 원본·투자기록으로 합산·증감·월말 선택·직접입력·자산 연동 값 확인.
- 키 발급 후(10/12~): 각자 '지금 갱신' → 실제 접속·응답 항목 이름 확인 → 증권사 앱 금액과 대조.

## 운영 적용
`migrate_couple.py`에 이어 붙이거나 같은 패턴의 마이그레이션으로: 백업 사본 → 탭 추가(투자, 한투원본, 투자기록)·
숨김·순서 → 수식·서식 → 스크립트 배포. 기존 입력 데이터는 건드리지 않는다. 기록은 적용한 날부터 쌓인다.

## 범위 밖
입출금 내역 기반 정확한 원금, 종목별 비교 그래프, 한투 일반(비 ISA) 계좌, 적용 이전 과거 데이터 복원.

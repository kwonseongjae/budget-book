# 다증권사 계좌 지원 설계 (2026-10-21)

## 1. 목표

메리츠·한투 ISA 외의 증권사 계좌도 `투자`·`주식투자` 탭에 합산한다. 증권사 제한 없음, API 키 불필요.
앞으로 증권사 API를 붙일 때 파일 하나만 추가하면 되는 형식(어댑터)을 만든다.

## 2. 범위

**하는 것**
- `증권계좌` 탭(계좌 목록)과 `증권종목` 탭(종목 표)을 추가한다.
- 붙여넣기 방식: 증권사 앱·홈페이지의 보유종목 표를 붙여넣으면 그 계좌의 종목이 교체된다.
- `투자` 탭 계좌 행이 목록 길이만큼 늘어나고(최대 10개), 소유자별 합계가 목록에서 계산된다.
- `투자기록`을 "한 줄에 한 계좌" 형식으로 바꾸고 기존 기록을 변환한다. 계좌가 목록에 생기면 다음 기록부터 자동으로 포함된다.
- 목록에 계좌를 추가하면 그 계좌의 상세 탭이 **자동으로 만들어진다** (§6).
- 메리츠·한투를 어댑터 형식으로 감싼다. 현재 값·화면은 그대로 유지한다.

**하지 않는 것**
- 키움·LS·미래에셋 등 새 API 연동 (어댑터 자리만 만든다).
- 붙여넣은 종목의 실시간 시세 (붙여넣은 값 그대로).
- 환전·주문 (조회 전용 원칙 유지).

## 3. 데이터 모델

### 3.1 `증권계좌` (입력 탭)

| 열 | 내용 |
|---|---|
| A 이름 | 계좌 표시 이름 (중복 불가, 예: `신랑 키움`) |
| B 소유자 | `설정` 사용자 드롭다운 (신랑/신부/공동…) |
| C 증권사 | 자유 글자 (표시용) |
| D 방식 | `자동(메리츠)` · `자동(한투)` · `붙여넣기` |
| E 예수금 | 붙여넣기 계좌의 현금 (직접 입력, 자동 계좌는 비움) |
| F 마지막 갱신 | 자동: 갱신 시각 / 붙여넣기: 마지막 붙여넣기 날짜 (스크립트가 씀) |
| G 상태 | 자동(수식): 정상 / 오래됨(붙여넣기 14일↑·자동 3일↑) / 미갱신 |

- 기존 4개 계좌(신랑·신부 × 메리츠·한투)는 마이그레이션이 이 목록의 1~4행으로 옮긴다. 이름은 현재 `투자` 탭 표기와 동일.
- 방식 `자동(...)`은 기존 `메리츠원본`·`한투원본`·`한투종목` 슬롯과 1:1로 연결된다 (새 슬롯은 만들지 않음 — 기존 API 계좌 수는 그대로 최대 4개).

### 3.2 `증권종목` (스크립트가 쓰는 정규 표)

`계좌 | 코드 | 종목명 | 수량 | 매입금액 | 평가금액 | 통화` — 계좌 이름 기준으로 행이 쌓인다.
- 붙여넣기 계좌: 붙여넣기 때 그 계좌의 행을 전부 지우고 새로 쓴다.
- 자동 계좌: 갱신 때 같은 형식으로 쓴다 (기존 `한투종목`·`주식_*` 탭은 유지, 거기서 복사).
- `주식투자`의 섹터·종목 비중과 `투자`의 원금·손익은 이 표를 읽는다.

### 3.3 `투자기록` (새 형식)

`날짜 | 계좌 | 평가 | 원금` 한 줄씩. 하루에 계좌 수만큼 줄이 쌓인다. 같은 날짜·계좌는 덮어쓴다.
- 합계·소유자별·전일 대비·그래프는 이 표에서 SUMIFS/피벗 수식으로 계산한다.
- 평가가 숫자가 아닌 계좌는 그날 기록하지 않는다 (지금의 "빠진 계좌" 규칙).
- 기록 시각은 지금처럼 매일 06시 일일 작업 한 곳.

## 4. 어댑터 형식

Apps Script 전역 함수 규약 (증권사 이름 `x`):
```
x_fetch(account) -> { ok, error?, value, principal, cash, holdings:[{code,name,qty,cost,value,currency}] }
```
- `account`는 `증권계좌` 한 행. 키는 사용자 속성에서 읽는다 (기존과 동일, 시트·git에 두지 않음).
- 메리츠(`meritz_fetch`)·한투(`kis_fetch`)는 기존 함수를 이 형식으로 감싼다. 동작은 바꾸지 않는다.
- `붙여넣기`는 어댑터가 아니라 입력 경로다 (`증권종목`에 직접 씀).
- 갱신 순서: 일일 작업과 증권 트리거가 목록의 `자동(...)` 계좌를 순서대로 `x_fetch` → `증권종목` 갱신.

## 5. 붙여넣기 파서

- 입력: 탭 구분(스프레드시트·웹 표 복사) 또는 쉼표 구분(CSV) 텍스트. 줄바꿈으로 줄 구분.
- 첫 비어 있지 않은 줄에서 **헤더 이름**으로 열을 찾는다. 인식 이름: 종목명/종목/상품명, 코드/종목코드/티커, 수량/보유수량/잔고수량, 매입금액/매입가액/투자원금, 평균단가/매입단가, 평가금액/평가액, 현재가, 통화.
- 매입금액이 없으면 `수량 × 평균단가`, 평가금액이 없으면 `수량 × 현재가`.
- 숫자: 쉼표·원·%·공백 제거, 괄호/마이너스 음수 허용. 해석 불가 줄은 `인식 실패`로 남기고 나머지는 반영.
- 헤더를 못 찾으면 아무것도 바꾸지 않고 안내 문구를 보인다 (기존 종목 유지).
- 결과 한 줄: `N종목 반영 / 실패 M줄`.
- 붙여넣기 칸은 비운 뒤 결과만 남긴다 (문자입력과 같은 방식).

## 6. 계좌 추가 시 탭 자동 생성 (사용자 요청)

`증권계좌`에 새 계좌 이름을 적으면(onEdit) 스크립트가 **그 계좌의 상세 탭 `계좌_<이름>`을 자동으로 만든다**:
- 내용: 계좌 요약(평가·원금·손익·수익률·예수금·마지막 갱신·상태) + 종목 표(`증권종목`에서 필터) + 종목별 비중 원형 그래프.
- 이름을 바꾸면 탭 이름도 따라 바꾸고, 목록에서 계좌를 지우면 탭은 **삭제하지 않고 숨긴다** (기록 보존).
- 붙여넣기 계좌의 붙여넣기 입력 위치는 `증권종목` 한 곳 (계좌 선택 드롭다운 + 체크). 상세 탭은 보기 전용.
- 기존 `주식_*`·`메리츠_*` 탭은 그대로 둔다 (자동 계좌의 상세 화면).
- 탭 이름 중복·금지 문자(`[ ] * ? : / \`)는 입력 시 막는다.

## 7. 화면 변경

- `투자`: 계좌 표 행 수 = 목록 길이, 소유자별 합계 행 자동, 한눈에 표·그래프는 새 `투자기록`을 읽는다. 직접입력 평가/원금(H·I)은 유지.
- `주식투자`: 종목 소스를 `증권종목`으로. 섹터 지정 표는 티커/종목명 기준 그대로.
- `자산` G열 연동 드롭다운: 목록의 계좌 이름을 보여 준다 (기존 `메리츠_신랑` 값은 마이그레이션이 새 이름으로 바꾼다).
- `시작하기`·`사용법`·README/USAGE에 안내 추가.

## 8. 마이그레이션 (운영 시트)

1. 시트 전체 사본 백업 (Drive 사본).
2. `증권계좌`에 기존 4계좌 행 생성, `증권종목`에 현재 메리츠·한투 종목 복사.
3. `투자기록`을 새 형식으로 변환: 기존 행(날짜, 4×(평가,원금))을 계좌별 4줄로 펼친다. 변환 전 원본은 `투자기록_옛` 탭(숨김)으로 보존.
4. **대조**: 변환 전후 날짜별 합계 평가·합계 원금이 일치해야 하고, 불일치 시 중단(롤백 = 사본 복원).
5. `투자`·`주식투자`·`자산` G열 수식/목록을 새 소스로 전환.
6. 모든 단계는 반복 실행해도 같은 결과여야 한다 (기존 migrate 규칙).

## 9. 테스트

- node: 붙여넣기 파서(다양한 헤더·CSV/탭·실패 줄·음수), `x_fetch` 래퍼가 기존 응답과 같은 값을 내는지, 투자기록 줄 생성·덮어쓰기·빠진 계좌 규칙, 계좌 추가 onEdit 라우팅(탭 생성/이름 변경/삭제→숨김).
- pytest: 신규 탭 구성, 투자 표 행 수 = 계좌 수, 변환 함수(옛 행 → 새 줄, 합계 불변), 마이그레이션 반복 안전.
- 통합: 임시 시트에서 붙여넣기 → 투자 합계·주식투자 비중·상세 탭 생성 확인. 운영 시트는 마이그레이션 후 오류 0 / 합계 대조.
- 실제 시트에서 onEdit/체크박스 경로를 실행하지 못하는 한계는 기존과 같다 (가짜 시트 + 사용자 확인).

## 10. 위험과 대응

| 위험 | 대응 |
|---|---|
| 투자기록 변환 오류로 과거 추이 손상 | 사본 백업 + 옛 탭 보존 + 합계 대조 후 전환 |
| 붙여넣기 형식이 증권사마다 다름 | 헤더 이름 기반 + 인식 실패 줄 표시, 못 읽으면 변경 없음 |
| 계좌 탭 자동 생성으로 탭이 많아짐 | 계좌당 1개, 목록에서 지우면 숨김, 최대 10개 |
| 붙여넣기 값 노후 | 상태 "오래됨" 표시 |
| 이름 규칙 | 코드·문서에는 신랑/신부만 (names.py), 실제 이름은 로컬 설정 |

## 11. 해석한 점 (확인 필요)

"투자기록에서는 연동된 계좌가 있을 경우 자동으로 탭 추가"를 다음 두 가지로 해석했다.
1. 계좌가 목록에 생기면 **투자기록에 자동으로 포함**된다 (§3.3).
2. 계좌마다 **상세 탭이 자동으로 만들어진다** (§6).
다르게 의도하셨다면(예: 투자기록 안에 계좌별 열/탭) 알려 주세요.
